# Loop Transformer 循环深度

**核心结论**：Loop Transformer 让一组**共享权重的层循环执行多轮**——同一套代码多跑几遍，每遍在前一遍的中间结果上继续精化。参数量（存储）不变，等效网络更深，推理链更长。对后端开发者而言，这不是把查找表造得更大（堆参数），而是让同一段代码迭代逼近更优解。

## 是什么

- **标准 Transformer**：每层在一次前向计算中只执行一次，数据单向流过 N 层后输出。
- **Loop Transformer**：让其中一组层循环执行多轮，执行顺序形如"层1→…→层N→层1→…→层N"，每一轮都在上一轮隐状态的基础上继续推演。
- **共享权重（Weight Sharing）**：循环的各轮复用同一套层权重，权重只存一份——这是"参数量不变"的前提（概念见 [[模型权重与参数量]]）。
- **溯源**：想法源自 2018 年的 Universal Transformer（权重共享的深度结构）。但权重共享在同等预训练计算量下效果弱于独立权重，因此主流路线长期没有采用它。

## 为什么需要

- 基础洞察：**记忆型任务受益于更多参数，推理型任务受益于更多有效计算**。长链路推理（大型软件工程、多步数学推导、物理控制）需要沿多步因果链持续推演，无法靠堆参数获得。
- 加深有两条路：物理堆层（存储与计算同时涨）与循环执行（只涨计算）。Loop 是后者——用计算换深度。
- 权重共享的风险决定了落地方式：从头预训练一个 Loop 模型成本高且收益不确定，因此成熟做法是**改造已完成预训练的基座**（见 [[预训练与后训练]]），以较小算力开销换取智能上限提升。

## 怎么工作

- 以"28 层做两轮循环"为例：28 层的权重只存一份，被执行两次，等效于一个 56 层的 [[神经网络层数与深度|网络]]——物理深度不变，等效深度翻倍。
- 代价结构：计算量近似翻倍；权重存储不变；真正难处理的是第二轮的中间状态——KV Cache（键值缓存）的显存与注意力索引的检索开销，需要专门的工程设计压平（GLM-5.4 的三项改动见 [[GLM-5.4 Loop Transformer 架构]]）。
- 每一轮如何"接着想"而不破坏已学到的表示，依赖对 [[隐状态与残差流|隐状态]] 的受控写回（门控限流），而不是整轮覆盖。

## 与后端概念的对应

| Loop 概念 | 后端类比 |
|---|---|
| 共享权重层循环多轮 | 同一段代码多轮迭代逼近近似解（迭代法），而非建更大的查找表 |
| 物理深度 vs 等效深度 | 部署的实例数 vs 实际执行的迭代轮数 |
| 循环带来的计算开销 | 用 CPU 时间换内存占用——资源换资源，看哪边便宜 |
| 改造基座而非从头训练 | 重构现有系统而非推倒重写 |
