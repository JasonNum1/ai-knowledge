# 模型权重与参数量

**核心结论**：模型学到的"知识"不是代码，也不是数据库里的行，而是一组**被训练出来的数值矩阵**——权重（Weights）。权重的总个数叫参数量（Parameter Count），是行业标称模型体格的通用度量：7B = 70 亿个参数，1T = 1 万亿个参数。对后端开发者而言，权重像一张**被机器学出来的巨型查找表**，而不是工程师手写的配置。

## 是什么

- **模型权重（Weights）**：神经网络中所有可学习的数值。训练的本质就是不断微调这些数字，让模型输出越来越正确；推理时它们只读不写。
- **参数（Parameters）**：与权重基本同义。"参数量"即这些数字的总个数——模型文件的体积主要由它决定。
- **共享权重（Weight Sharing）**：默认网络中每个位置有独立权重；共享 = 多个位置复用同一套权重，存储减半，代价是同等训练算力下效果弱于独立权重（详见 [[Loop Transformer 循环深度]]）。

## 为什么需要：参数量是"体格"的通用标尺

- 历史上模型效果随参数量增长呈现很强的规律（Scaling Law，规模定律），参数量级因此成为行业通用的能力对标口径。
- 单位阶梯：M（Million，百万）→ B（Billion，十亿）→ T（Trillion，万亿）。
- 读法示例："750B 模型" = 7500 亿参数；"2-3T 级模型" = 参数量在 2–3 万亿量级的模型。GLM-5.4 自身约 750B 级参数，官方称其智能水平达到 2-3T 级模型——即用 750B 的存储干出了 2-3T 体格模型的活，差额来自架构带来的深度计算而非更多参数（见 [[GLM-5.4 Loop Transformer 架构]]）。注意这类对标是厂商自评口径，不是第三方实测指标。

## 怎么工作

- 训练阶段：数据前向计算 → 与目标比对得损失 → 反向传播（Backpropagation）更新权重，循环往复。
- 推理阶段：权重固定，输入数据流过网络产生输出；同一份权重可服务海量请求——这就是模型服务（推理服务）的成本模型：显存放权重、算力跑前向。

## 与后端概念的对应

| 概念 | 后端类比 |
|---|---|
| 权重 | 被机器学出来的巨型查找表 / 数值化的业务规则库 |
| 训练 | 离线跑批调整规则参数，直至误差收敛 |
| 推理 | 只读缓存的服务实例：数据（权重）不变，请求（token）流动 |
| 参数量 | 存储规模的粗略度量，类似"代码行数"之于软件复杂度——相关但不是能力保证 |
