# 隐状态与残差流

**核心结论**：隐状态（Hidden State）是 token 在网络各层之间流动时携带的"当前理解"向量——像流水线各站之间传递的**上下文对象**。残差流（Residual Stream）是承载它的主干通道，每层对它做**小比例的增量修改**而非整体覆盖——类似"改动按比例合入主干分支"。

## 是什么

- **隐状态**：token 被切分并转为向量（嵌入，Embedding）后进入网络，每经过一层就更新一次。这些**中间时刻的向量**统称隐状态："隐"指它们是内部中间量，不是最终输出。每个向量有几千个数字（维度 = 每层宽度）。
- **残差流**：Transformer 的层间主干通道。每层不直接替换隐状态，而是把本层的计算结果**按比例叠加**到通道上——残差（Residual）连接因此得名。

## 为什么需要

- 隐状态是信息逐层精化的载体：输入只表达字面含义，每过一层就多融合一层上下文与推理，最终层读出的隐状态用于预测下一个 token。
- 对 [[Loop Transformer 循环深度|循环架构]] 尤其关键：第二轮循环不是从头算，而是在第一轮留下的隐状态上继续精化——隐状态就是跨轮传递的工作状态。
- 残差连接解决了深层网络难以训练的问题：小步增量保证梯度可以稳定回传，也让"每层只做局部修改"成为可能。

## 怎么工作

- 写回规则：`新隐状态 = 旧隐状态 + 门控值 × 本层计算结果`。
- 若某轮计算结果幅度过大（激活范数 Activation Norm 膨胀），会破坏通道上已积累的表示——因此需要**门控（Gating）**按比例限制写入幅度：这是循环架构稳定运行的必要条件，GLM-5.4 的门控分工细节见 [[GLM-5.4 Loop Transformer 架构]]。

## 与后端概念的对应

| 概念 | 后端类比 |
|---|---|
| 隐状态 | 请求作用域的上下文对象，沿调用链逐站读写 |
| 残差流 | 受保护的主干分支——每层只能提交增量 |
| 门控写回 | 改动按比例灰度合入主干，防止单次变更破坏整体 |
| 激活范数膨胀 | 大变更导致主干状态漂移，下游节点（后续层）读到陌生分布 |
