# 预训练与后训练

**核心结论**：大模型的训练分两大阶段——**预训练（Pre-training）**用海量文本学语言与世界知识，产出博学但不会"听话"的**基座模型（Base Model）**；**后训练（Post-training）**把基座调教成能听指令、可对话的助手。对后端开发者而言：预训练像通读全部源码自学，后训练像按团队规范做的上岗培训。

## 是什么

| 阶段 | 做什么 | 产出 |
|---|---|---|
| **预训练（Pre-training）** | 用海量文本（万亿 token 级语料）做"预测下一个词"训练，学语言规律与世界知识 | 基座模型：会知识和语言，但不会指令对话 |
| **后训练（Post-training）** | SFT（Supervised Fine-Tuning，指令微调）+ 基于人类反馈的对齐（如 RLHF），把基座调成可用助手 | 实际交付的对话/编码模型 |

- **SFT**：用"指令 → 优质回答"的示例数据继续训练，让模型学会按指令行事。
- **RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）**：人类对模型输出打分，训练奖励模型再反向优化，让输出对齐人类偏好。
- 预训练成本极高（数千张 GPU 跑数月），后训练相对便宜——所以基座是稀缺资产，后训练是在基座上叠加的轻量改造。

## 为什么需要

- Scaling Law 下，智能的主要来源是预训练的规模（数据量 × 参数量 × 计算量）；没有预训练就没有能力基线。
- 基座只完成了"知识与语言"，距离可用产品还差行为对齐——两阶段缺一不可。
- 基座的稀缺性决定了架构创新的落地路径：**从头预训练一个新架构风险高、成本大；在已完成预训练的基座上做结构改造（继续训练）是性价比更高的选择**。GLM-5.4 正是改造 GLM-5 基座引入 Loop 结构而非从头预训练，改造前还需在 1B→750B 逐级规模验证改造有效（Scaling Correctness，详见 [[GLM-5.4 Loop Transformer 架构]]）。

## 怎么工作

1. 预训练：海量语料切片 → 前向预测下一个词 → 计算损失 → 反向传播更新 [[模型权重与参数量|权重]]，循环数万亿次。
2. 后训练：指令数据 SFT → 人类偏好数据训练奖励模型 → 强化学习对齐。
3. 架构改造（Loop 类）：冻结思路不设硬性冻结，在预训练完成的权重上以较低学习率继续训练，把部分层改为循环结构，让权重适应新的执行方式。

## 与后端概念的对应

| 概念 | 后端类比 |
|---|---|
| 预训练 | 通读全部源码自学——掌握领域知识但不懂团队流程 |
| 后训练（SFT/对齐） | 按团队规范的上岗培训——把知识调成可用的工作行为 |
| 基座模型 | 经过完整培训的通用工程师底座 |
| 改造基座引入新架构 | 重构现有系统而非推倒重写——保留已验证的能力，只改执行结构 |
| Scaling Correctness 逐级验证 | 大重构先在小流量/灰度环境验证，再全量铺开 |
